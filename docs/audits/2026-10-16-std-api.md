# Orin standard library: public API consistency audit

Repo `/home/claude/orin` at `1b8e1a8`. Scope: `std/*.or` (prelude), `array/*.or` (the other implicit prelude: `map`, `filter`, `Map`, `std:math`, `parallel()`), `stdlib/*.or`, the builtin method tables (`compiler/check/builtins.or`, `compiler/check/ops.or`, `compiler/check/expr.or`, `compiler/check/ints.or`), `compiler/mcp/apitable.or`, `docs/std*.md`, `spec/08-standard-library.md`, ADR-0034, ADR-0040.

Counts are produced by a regex scan of `export function` + public class methods. Treat them as +-3 accurate, not exact. `file` means `stdlib/file.or` unless a directory is given.

Spec 08 already states the governing principle (`spec/08-standard-library.md:5`): "JavaScript/TypeScript-familiar names", "no nullable results", "no throw-on-ordinary-failure", "no hidden shared mutable array methods". Several findings below are deviations from that, not just from each other.

## (d) Proposed rename / reshape list

"Breaking" = source-breaking for current users of the public name. Unstable modules (`fs`, `host`, `net`, `task`, `time` monotonic part, per `docs/std.md` "UNSTABLE") are marked `[unstable]`; breaking changes there are cheap. Keep the old name one release as `@Deprecated` wrapper where noted (ADR-0040 sets this precedent).
