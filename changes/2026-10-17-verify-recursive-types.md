- **Contract verifier: recursive records, classes and unions (ADR-0053 Addendum A).** `orin verify --contracts` gave UNKNOWN for every clause that read or wrote a field of a type that reaches itself ("the fields of the recursive type `FnCtx` are not modelled"), built a variant of a recursive union, or matched on one. Such a type now has an uninterpreted sort with an accessor function per field (a union: per payload and a tester per variant), a constructor function and the selector axiom of a datatype, so field reads and writes, record literals, variant construction, `match` and the frame facts of mutating methods are reasoned about like those of any other record, class or union (value semantics, A-INV and A-FRAME as before). Because a model of the solver need not be a finite value, a function that uses a recursive type never gets a counterexample: a wrong claim stays UNKNOWN, never VERIFIED. Regression test: `tests/contracts/verify_rectypes.or`.
