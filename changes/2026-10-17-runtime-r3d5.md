- **Stats, live count and the allocation-site census on the Orin object model (ADR-0052 R3d.5).** The `ORIN_STATS=1` report (`orin_stats_report`) and `orin_live_count` are Orin functions of the embedded runtime (`runtime/core/stats.or`), and census builds (`--stats-sites`) now run the same Orin allocator, `destroy`, copy-on-write and string/array functions as every other build: the site that allocated an object is a prefix word of 8 bytes before its header (so the object layout is the same in all builds), the census counters and its report stay in C and are reached through a new core operation `hook` (number 27, `orin_core_hook`, which also serves the report's environment, stderr, runtime-lock and finished-task-totals needs). All `#ifdef ORIN_SITE_STATS` C copies of the allocator and of the string and array functions are deleted. `ORIN_STATS` counters and `tools/alloc_census.py` per-site, pair and call tables are unchanged (the census summary's `peak_live_bytes` is now the normal build's, not 8 bytes per object more); the step itself leaves executed instructions unchanged (within +-0.02 % on both backends, `selfcompile` +0.09 %), and a fix of `appendDecimal` (it counted digits by repeated division, which cost R3d.4 +1.4 % on `mapfreq` with LLVM; it now counts by comparison) takes `mapfreq` and `wordfreq` down by 2 % and `html_hand`, `html` and `strings` by 1 to 2 % on C.
