# ADR-0034: `Eq`, `Ord` and `Hash` constraints on type parameters

Status: accepted (2026-10-14; three-tier rule from the project owner). Additive to the frozen language core (ADR-0016 rule: additive
features after the freeze need an ADR). Related: ADR-0019 (interfaces), ADR-0026 (generic
classes with `T extends I` bounds), ADR-0030 (std uses the best known algorithm), ADR-0031
(contracts over generic values).

## Context

`==`, `<` and hashing are not available on a type parameter, and `Map` keys must be concrete
`int`/`usize`/`bool`/`string`. As a result the std ships `IntSet`/`StringSet` and int/string-only
`SortedMap`s instead of `Set<T>`/`SortedMap<K, V>`. Generic containers cannot state "the value you
get back equals the value you put in" in their contracts.

## Decision

1. **Three built-in constraint interfaces:**
   - `Eq` gives `==`/`!=`;
   - `Ord extends Eq` gives `<`, `<=`, `>`, `>=` and `compare`;
   - `Hash extends Eq` gives a hash used by `Map`/`Set`.

   They are used like any bound: `class Set<T extends Hash>`, `function max<T extends Ord>(...)`.
2. **Three tiers** (project owner, 2026-10-14):
   1. **Automatic derivation for simple value types.**
      - `int`, the fixed-width integers, `usize`, `bool` and `string` are `Eq + Ord + Hash`.
      - Records, enums/tagged unions, `Option`, `Result` and arrays are derived structurally:
        `Eq`/`Hash` when all their components are, and `Ord` lexicographically when all
        components are `Ord`.
      - Derived instances are generated by the compiler and are correct by construction. Their
        laws are proved once for the derivation scheme, so they create no per-type obligation.
      - Floats are **not** `Eq`/`Hash` (NaN). Ordering them needs an explicit `totalOrder`
        wrapper, and a record containing a float derives nothing.
   2. **Explicit implementation for domain-specific semantics.**
      - Classes, and any record or enum whose equality is *not* structural, declare `equals`,
        `compare` and/or `hash` themselves, with contracts. Examples:
        - `Money` compares amount and currency, but not a display format;
        - `Email` compares case-insensitively in the domain part;
        - `Version` orders numerically, not lexicographically.
      - An explicit implementation replaces derivation for that type.
      - A class can request structural derivation with `implements Eq` and no methods.
   3. **Formal proof for user-defined implementations in strict mode.**
      - Every explicit implementation must satisfy its laws:
        - reflexive, symmetric and transitive `equals`;
        - `compare` a total order consistent with `equals`;
        - `a == b ⇒ hash(a) == hash(b)`.
      - In a normal build the laws are checked by generated `@Property` tests (ADR-0031 §17,
        `TESTED_ONLY`).
      - In strict mode (ADR-0035) each law is a mandatory proof obligation. If one is not
        `VERIFIED`, the strict build fails with `NEEDS_DECISION` (ADR-0029); `TESTED_ONLY` is
        not enough.
3. **Laws in the verifier.** For Z3, `Eq`/`Ord` on a type parameter `T` are uninterpreted
   relations with exactly the laws above as axioms, so generic container contracts become
   verifiable. That is sound because every instance either is derived (proved once) or is checked
   or proved per tier 3.
4. **`Map<K, V>` accepts `K extends Hash`.** The existing concrete key types keep working
   unchanged.
5. **No implicit instances for function values or resources** (handles). They are neither `Eq`
   nor `Hash`.

## Consequences

- `std:collections` gets `Set<T>`, `SortedMap<K extends Ord, V>` (B-tree) and
  `PriorityQueue<T extends Ord>`. The int/string versions become aliases or are removed before the
  std I/O freeze.
- Generic container contracts can state value equality ("get after put returns the value").
- This needs checker, lowering (instance dictionaries or monomorphised `==`/`hash`), VC and docs
  work. It comes after rewrite step 2b, because it touches the checker's body rules, and before the
  std I/O freeze, because it changes the collection APIs. `std:net`/`std:http` do not depend on
  it: header maps use string keys.
