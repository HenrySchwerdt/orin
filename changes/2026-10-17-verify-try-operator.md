- **Contract verifier: `?` and calls of mutating methods inside an expression.** `orin verify --contracts` gave UNKNOWN for every function with `e?` ("`?` (early return on Err / None) is not supported") and for every call of a mutating method that is not a whole statement, e.g. `this.next() + this.next()` or `Ok(this.parseType()?)` ("call of the mutating method `X` inside an expression"). Such effects are now executed as statements before the expression, in the order the expression evaluates them (everything read before an effect is bound first, so the order of reads, effects and traps is kept), for a statement, a `let` initialiser, an assigned value, a `return` value (also the arms of a `return match`) and an `if` condition. `e?` returns `Err(payload)` of the function's own result type when `e` is Err, so every `@Ensures` and class invariant is checked on that early-return path as well as on the normal one; a wrong claim there is REFUTED or UNKNOWN, never VERIFIED. An effect whose order of evaluation cannot be kept (right operand of `&&` / `||`, a `?:` branch, a `match` arm, a `while` condition) stays UNKNOWN with its reason. Regression test: `tests/contracts/verify_try.or`.
